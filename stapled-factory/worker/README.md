# Worker integration status

The production entry point returns `blocked`. The adapter and attempt ledger can be exercised independently, but are not connected to an authorized production sandbox or enabled by Restate. An unknown result must not be redispatched. The Restate workflow records the attempt and conversation IDs and marks `needs_reconciliation`. A separate keyed reconciliation workflow polls only the original attempt; verified completion is held at `needs_validation` until the wall target can be bound to the recovered revision. The production reconciliation entry point currently remains blocked.

`execute_bound_attempt` connects the guarded attempt reservation to one-shot provisioning and checks the bound allocation before creation or read-only reconciliation. Its adapter factory and configuration must come from a trusted coordinator; the primitive does not establish their trust or enable the production entry point.

`egress_proxy.py` and `egress_bridge.py` are candidate controls for a networkless worker. The proxy holds the gateway key separately, restricts the HTTP method/path, fixed upstream and model, bounds output tokens and durably reserves a request before forwarding. Its monetary reservation rejects requests exceeding an explicitly configured limit using a trusted worst-case per-request price. It is not a verified billing cap until that price, all fees and model limits are established for the account. Both its budget ledger and independent watermark must be preserved. A lost or replaced budget database must not be treated as an unused budget. The worker may receive only a read-only Unix socket volume and an independently validated isolated workspace; do not mount the budget database or credentials into it.

The proxy rejects unknown top-level request options and image, document, audio and video blocks, as well as provider-hosted tools. This narrows the set of features a pricing policy must cover; it does not establish a complete price bound or control charges incurred by the gateway itself.

`egress_guard.py --mode networkless --worker NAME --proxy NAME --uplink-network NAME --socket-volume NAME --budget-volume NAME --anchor-volume NAME` inspects Docker topology. The expected socket mount is `/gateway`, the budget mount is `/budget`, the independent anchor mount is `/anchor`, and both containers must use explicit non-root numeric UIDs. If a workspace bind is required, add `--workspace-source /absolute/isolated/path`; validate its provenance and contents separately. The checker cannot establish image or process identity, exclude subsequent privileged topology changes, prove exclusive workspace ownership, or prove the proxy's code/configuration. A passing inspection is not authorization to enable dispatch.

OpenHands can preserve a stale running status after server death; lease expiry and hydration can convert it to an error even where prior tool effects remain unknown. Do not re-run an interrupted conversation merely because it reports an error or accepts `/run`. Preserve the attempt store, original workspace, server state and event history; reconcile before any further dispatch. Initialize and check the guarded attempt ledger with `guarded_store.py` and retain its watermark independently. A mismatched, missing or older ledger is quarantined; a coordinated rollback of both ledger and watermark cannot be detected without an external authority. The guarded store is not yet wired to the blocked production entry point.

The user-selected recovery policy permits a fresh isolated successor after fencing the old worker, subject to the same $2 budget. `successor_runtime.py` is an experimental provisioning-only path that reuses the original proxy and ledger; it cannot dispatch a task. Real charge bounds, trusted image and workspace provenance, and independent rollback protection remain required before enabling it.

Disposable probes: `python3 worker/probes/crash_recovery.py` kills a pinned Agent Server while a loopback-only mock model request is in flight. `python3 worker/probes/controller_recovery.py` kills the controller while the server remains alive; it uses a synthetic model and revision verifier. `python3 worker/probes/verify_gateway_isolation.py` exercises the provisioner and actual proxy with an invalid gateway key; it expects direct TCP denial and a gateway authentication rejection. These probes require Docker, create and remove their own resources, and do not establish production image trust, billing, or successful server-crash recovery.
