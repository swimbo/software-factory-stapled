# Paired harness evaluation

`deployment/nuc/evaluation_trials.py` is a trusted operator command, outside the worker tool surface. Prepare a separate private setup, immutable task/seed/check digests, a complete schedule and signed runtime inputs before invoking it. Keep the candidate runtime frozen before creating held-out tasks. Never mount the independent oracle in a worker or pass it to a candidate optimizer. These development checks are separate from private wall and production acceptance.

The pilot matrix compares baseline, context-v1, context plus bounded-native-v1, and the combined stall-v1 configuration on the same task revision. Compare adjacent profiles to describe each extension, and baseline against the combined configuration. Context-v1 is itself a bundle; its result cannot attribute savings to individual prompt/tool/skill changes. Counterbalance the first baseline/context pairs and record fixed execution order. One repeat across six distinct tasks provides descriptive pilot evidence, not a benchmark or robust estimate of run-to-run variance.

Every unit has a fresh identity. Durable dispatch intent prevents a repeated model execution after interruption. `--observe-only` requires an existing intent and saved owned binding; it only collects and contains that original allocation. Completed receipts can be published after binding restoration without another dispatch. Polling I/O failure contains the original identity and preserves its intent, reservation and uncertainty. A pre-binding failure is a failed zero-call sample only when the returned coordinator state, missing durable credential binding, absent namespace and canonical gateway evidence establish zero activity; otherwise observation stops with uncertainty.

Worker results require a clean exact revision, allowed paths and an independent isolated checker of frozen candidate bytes. Execution predicates are separately frozen in the schedule. A diagnostic task requires one recorded Python import attempt; file output alone is insufficient. The command auditor recognizes recorded Python snippets and quoted heredocs, not arbitrary dynamic shell/Python behavior. Unsupported or missing evidence never counts as a verified import. Candidate code runs in a child of the oracle process so exiting the candidate with status zero cannot bypass the parent assertions. This does not make development checks an adversarial private wall.

Baseline SDK state uses temporary storage; bounded metadata is reduced through the original SDK before stopping it and fsynced for collection recovery. Bounded profiles retain SDK state in the workspace and audit it after the original namespaces stop. Only counts and command hashes leave these reducers. The pinned event contract lacks authoritative truncation coverage, which remains unknown. An absent intervention requires complete metadata and no diagnostic delivery; uncertain intervention evidence remains unknown.

`harness_evaluation.evaluate(preregistration, results)` rejects missing, duplicate or mismatched samples. It sums all consumption, including failed trials, before dividing by independently accepted tasks. Input tokens include reported input, cached reads and cache creation; missing coverage propagates. Canonical gateway request IDs, prompt/output/cache totals and estimated reservations must reconcile with retained wire metadata and ledgers. Report actual provider/served-model strata; a differing route prevents unqualified promotion. Estimated reservations are not actual charges or a charge cap.

Freeze input tokens per accepted task as the primary metric before any candidate run. Eligibility requires no accepted-task decline (also no lost paired task), at least 10% primary improvement, median elapsed time no more than 10% worse, regression gates, complete accounting, known truncation coverage and zero stall false positives. Eligibility is evidence for a decision, never authority to merge, deploy or alter defaults. Missing gates retain the baseline. Profiles remain explicit rollback switches; restoration never rewinds ledgers or replays an attempt.

The evidence predicates must match the visible task contract. A failed subcommand followed by status printing can leave an overall shell exit of zero; required JSON fields do not imply an exact key set. Preserve frozen scores and append independently checked contract reconciliation instead of changing original receipts or rerunning models. The [October 31 pilot](../../docs/verification/harness-evaluation-2026-10-31/report.md) records both cases and retains the baseline because qualification evidence remains incomplete.

Fresh qualification cohorts may preregister `repeats_per_task` as a positive integer. Every schedule and result row then carries `repeat` from 1 through that count. Pairing uses task, repeat, and profile; every failed attempt remains in consumption, and a lost paired acceptance blocks promotion even when aggregate acceptance ties. Repetitions measure run-to-run variation; they do not increase the number of independent tasks. Legacy cohorts default to one repeat and retain their original comparisons.

A signed sandbox runtime can opt into `evaluation_observation: "sdk-poll-v1"` for read-only SDK observation at two-second sleeps, with at most 120 observations per call. Control profiles observe their original conversation directly instead of waiting for the ordinary 30-second orchestration reconciliation interval. Stall profiles retain their existing observer without a second polling loop. Runtime and bound-allocation validation precede every control observation; this adds overhead, so equal nominal cadence is not identical end-to-end timing. Timeout or uncertainty retains the original reservation for read-only reconciliation. The flag refuses successor modes and never issues another conversation creation, `/run`, diagnostic, cancellation, or budget change.
