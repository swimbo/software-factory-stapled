# Controlled-build local smoke — November 1, 2026

Two synthetic local fixtures exercised fixed offline recipes with a dedicated BuildKit container and pinned local OCI bases. The NUC runtime and existing factory attempts were not changed. The Docker daemon, BuildKit image and host were trusted; the daemon was privileged and configured with Buildx's `network.host` entitlement, while neither fixed build request granted `--allow` and both passed `--network none` with `RUN --network=none`. This is not proof of resistance to a malicious build escaping its sandbox or of publisher authenticity.

The first build failed with `ENOTCACHED` because the cache was populated in the wrong directory; the failed attempt is retained. After the cache-path fix, a new attempt succeeded. A separate real build through the signing wrapper produced a v2 manifest; its Ed25519 fixture signature, exact archive digest and image configuration verified. A Rust 1.83 synthetic project compiled offline in a pinned local Rust 1.83 image; its image archive has a release binary represented as a hard link to the compiled file. Image archive SHA-256: `6774c2379ce827e05a1a42b3632888c884ba12d7455d83ffd3a9a175365b9bf9`. Both builds used exact source and material digests and no model calls. The npm and Cargo preflights also passed against their respective retained inputs. The image verifiers check Docker configuration and layer hashes. The controlled verdict remains **incomplete**: image build and signing alone do not establish publisher identity, complete dependency coverage, production application behavior, or a releasable NUC runtime. No application was published or comparison trial run.
